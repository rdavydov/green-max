# GREEN MAX

Минимальный чат на React и TypeScript для обмена текстовыми сообщениями в MAX через [GREEN-API MAX](https://green-api.com/max). Интерфейс основан на [веб-версии MAX](https://web.max.ru/): список чатов слева, переписка справа, отдельный экран чата на телефоне.

- [Репозиторий](https://github.com/rdavydov/green-max)
- [Инструкция для локального запуска](https://github.com/rdavydov/green-max#локальный-запуск)
- [Адрес GitHub Pages](https://rdavydov.github.io/green-max/) — публикация требует успешного запуска workflow и включения Pages в настройках репозитория.

## Локальный запуск

Требуется Node.js 24 LTS и npm. Команды подходят для PowerShell, macOS и Linux:

```sh
git clone https://github.com/rdavydov/green-max.git
cd green-max
npm ci
npm run dev
```

Откройте адрес, выведенный Vite в терминале; при стандартных настройках это [http://localhost:5173/](http://localhost:5173/).

По умолчанию используется `https://api.green-api.com/v3`. Если для вашего инстанса нужен другой `apiUrl` из кабинета, скопируйте пример локального окружения:

```sh
cp .env.example .env.local
```

В `.env.local` измените только `VITE_GREEN_API_URL`, указав адрес API с суффиксом `/v3`. После изменения перезапустите dev-сервер; для production выполните сборку заново. Переменные с префиксом `VITE_` попадают в браузерную сборку, поэтому `idInstance` и `apiTokenInstance` в конфигурацию добавлять нельзя — вводите их только в интерфейсе. `.env.local` исключён из Git.

Для проверки production-сборки:

```sh
npm run build
npm run preview
```

Откройте [http://localhost:4173/green-max/](http://localhost:4173/green-max/). Путь `/green-max/` соответствует названию репозитория на GitHub Pages.

## Подготовка GREEN-API

1. Создайте MAX-инстанс в [личном кабинете GREEN-API](https://console.green-api.com/) и авторизуйте связанный аккаунт MAX. Состояние инстанса должно быть `authorized`.
2. В настройках инстанса оставьте `webhookUrl` пустым и включите входящие уведомления (`incomingWebhook: "yes"`). Эти настройки необходимы для получения сообщений через HTTP API.
3. Для статусов доставки и прочтения включите `outgoingWebhook: "yes"`. Для уведомлений об отправленных через API сообщениях включите `outgoingAPIMessageWebhook: "yes"`; для сообщений, отправленных с телефона или из MAX Web, — `outgoingMessageWebhook: "yes"`.
4. Сохраните настройки и дождитесь их применения: это может занять до 5 минут. Для `SetSettings` этот срок указан в [документации GREEN-API](https://green-api.com/v3/docs/api/account/SetSettings/).
5. На экране приложения введите `idInstance` и `apiTokenInstance` из кабинета и нажмите «Подключиться». Приложение проверит состояние и настройки инстанса, не меняя их.
6. Нажмите «Новый чат», введите номер получателя в международном формате и создайте чат. `CheckAccount` проверит наличие аккаунта и вернёт идентификатор чата MAX.
7. Отправьте текст, ответьте с аккаунта получателя в MAX и дождитесь ответа в браузере.

Поиск по телефону может быть запрещён настройками приватности получателя. В таком случае создание чата показывает ошибку; это ограничение MAX.

Документация: [SendMessage](https://green-api.com/v3/docs/api/sending/SendMessage/), [HTTP API и настройка уведомлений](https://green-api.com/v3/docs/api/receiving/technology-http-api/), [ReceiveNotification](https://green-api.com/v3/docs/api/receiving/technology-http-api/ReceiveNotification/), [DeleteNotification](https://green-api.com/v3/docs/api/receiving/technology-http-api/DeleteNotification/), [настройки инстанса](https://green-api.com/v3/docs/api/account/SetSettings/).

## Поведение и ограничения

- Поддерживаются личные чаты, текст и текст с URL, до 4000 символов. Вложения, группы, звонки, редактирование и удаление сообщений не реализованы. Для создания чата поддерживаются номера РФ (`+7`) и Беларуси (`+375`).
- `SendMessage` возвращает идентификатор принятого сообщения; это ещё не подтверждение доставки. Статусы «Доставлено» и «Прочитано» обновляются по уведомлениям, если они включены на инстансе.
- Токен хранится только в памяти вкладки: он не записывается в localStorage, репозиторий или настройки сборки. После обновления страницы его нужно ввести снова. API вызывается непосредственно из браузера, поэтому токен виден владельцу браузера в инструментах разработчика.
- Чаты и полученная история сохраняются в localStorage отдельно для каждого `idInstance`. Они доступны только в данном браузере и на данном адресе сайта. Полная история MAX с сервера не загружается; удаление данных сайта удаляет локальную историю. Кнопка выхода сохраняет историю и завершает сессию приложения, не разлогинивая аккаунт MAX.
- Для предотвращения конкуренции вкладок используется Web Locks API. Нужен современный Chrome, Edge, Firefox или Safari, HTTPS либо localhost. Вторая вкладка с тем же инстансом не подключается до выхода из первой.
- Используйте один потребитель очереди уведомлений для данного инстанса. Другая программа или браузер на другом устройстве могут забрать уведомления раньше приложения. `DeleteNotification` удаляет событие безвозвратно; текст сохраняется локально перед подтверждением. Повторные события не добавляют дубликаты. Неподдерживаемые уведомления подтверждаются без отображения.
- Входящая очередь GREEN-API хранит уведомления 24 часа. При проблемах сети приложение показывает состояние переподключения и повторяет получение с задержкой. При ошибке локального сохранения получение приостанавливается.
- При сетевой ошибке отправки текст остаётся в поле. Автоматической повторной отправки нет: сервер мог принять сообщение до разрыва соединения. Перед ручной повторной отправкой проверьте чат в MAX.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npx playwright install --no-shell chromium
npm run test:e2e
npm run build
```

Браузерные проверки используют Chromium и перехватывают HTTP-запросы GREEN-API. Проверяются обмен текстом и URL, два чата, статусы, дедупликация, перезагрузка между сохранением и ACK, отсутствие сохранённого токена, ошибка отправки, две вкладки, выход во время long polling и размеры 1440×900 / 360×780. React StrictMode включён и в этих сценариях.

Эти тесты не отправляют сообщения в реальный MAX. Реальный обмен требует действующего авторизованного инстанса и второй учётной записи: пользователь вводит свои ключи в интерфейс самостоятельно. Успешный реальный обмен отдельно фиксируется после такой проверки; автоматические проверки и демонстрационные скриншоты не являются её подтверждением.

## Публикация на GitHub Pages

Workflow [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) запускается при push в `main`, pull request и вручную через Actions. Он устанавливает зависимости, проверяет типы, lint, unit- и браузерные тесты, собирает проект и публикует `dist` после успешных проверок. Pull request выполняет проверки без публикации.

В репозитории откройте **Settings → Pages → Build and deployment → Source: GitHub Actions**. Затем отправьте изменения в `main` или запустите workflow вручную. В сборке установлен базовый путь `/green-max/`; итоговый адрес — [https://rdavydov.github.io/green-max/](https://rdavydov.github.io/green-max/). Ключи GREEN-API для публикации и CI не нужны.

## Стек

React, TypeScript, Vite, CSS, Vitest / Testing Library, Playwright. Статическое SPA без собственного сервера и без SDK: небольшой HTTP-клиент вызывает GREEN-API, обработчик уведомлений управляет очередью, localStorage хранит полученную историю.
